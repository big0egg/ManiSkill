# 相机与操作区 crop 实验（PickCube 详细报告）

另外四个任务的推荐参数、点数分布和限制见
[MULTI_TASK_REPORT.md](MULTI_TASK_REPORT.md)。以下部分是 PickCube 的较大样本实验。

所有实验程序、缓存、录制数据、统计和图片均在此目录内。本报告记录相机筛选阶段；
用户确认后已将推荐参数正式接入任务与FlowDP3流程，接入及验证见 [INTEGRATION.md](INTEGRATION.md)。

本实验优先评价目标物体，其次腕部/夹爪。固定 crop 为机器人基座坐标系
`min=(0.44,-0.23,-0.03)`、`max=(0.79,0.25,0.52)` 米，在减 TCP 前应用。
允许裁去部分机械臂，不要求保留整臂。所有相机位置和朝向使用**世界坐标系**。
Panda 基座世界位置约为 `(-0.615,0,0)`，这两个坐标系不能混用。

## 推荐配置与结果

按最终方块点数的低分位和中位数，推荐 `low_left256_60`：

| 参数 | 值 |
| --- | --- |
| 相机位置 eye（世界系、米） | `(0.30,-0.30,0.35)` |
| 注视位置 target（世界系、米） | `(0,0,0.12)` |
| 分辨率 | `256×256` |
| 垂直视场角 | `60°`，传入 CameraConfig 的弧度值为 `π/3` |
| 传感器 | `base_camera`，shader_pack=`default` |
| 主评估点数 | FPS512，另记录 FPS1024 对照 |
| 预采样 | 最多4096点，随机种子42，保持现有算法 |

7条未参加 RGB/FPS 筛选的完整轨迹，593帧，比较结果如下。数值为每帧点数；
所有相机使用同一个操作区 crop，表中的差异仅来自相机设置。

| 配置 | 原始方块中位数 | FPS512 方块最少 / P05 / 中位数 / 最多 | FPS512 腕部最少 | 方块零点帧 |
| --- | --- | --- | --- | --- |
| 原相机：128×128、90°、eye=(0.3,0,0.6) | 23 | 3 / 4 / 8 / 14 | 45 | 0 |
| 较高右斜视：256×256、50°、eye=(0.28,0.24,0.50)、target=(0,0,0.17) | 425 | 3 / 5 / 10 / 16 | 31 | 0 |
| 较低右斜视：256×256、60°、eye=(0.3,0.3,0.35) | 420 | 3 / 4 / 10 / 16 | 9 | 0 |
| **推荐左低斜视：256×256、60°、eye=(0.3,-0.3,0.35)** | **476** | **4 / 7 / 11 / 18** | **8** | **0** |

推荐配置在上述593帧的可见方块点于 crop 阶段全部保留，腕部/机器人持续有点。
但是最高抬升等少数帧仅剩8个机械臂点；较高右斜视保留腕部更稳，可作为备选。
这正是物体优先与机械臂覆盖的取舍，不能称为完整机械臂保留。

推荐配置的方块点数中位数为：原始476 → crop476 → 随机预采样72 → FPS512后11。
原始观测明显改善，最终采样的提升有限，尚未达到每帧几十至上百个目标点。
仅提高原相机分辨率至256/384时，筛选样本的FPS512方块中位数仍为7；
相机位置、视角和后续采样都影响最终覆盖。不能将原始像素增加倍数视为FPS点数增加倍数。

## 实验方法与边界

- 数据来源：`.runtime/flow_dp3/pickcube-100-scene-v3.raw.h5`，120条成功的
  Panda `pd_joint_pos` 专家轨迹；源文件和对应JSON的SHA256保存在每个manifest中。
- 第一轮渲染19种配置，第二轮再渲染5种，共24种。两轮均使用源episode
  `0 2 4 6 8` 的相同70个状态，各配置都重新渲染相同状态，总计1680个状态/配置样本。
- 完整渲染验证使用episode `1 3 9 19 27 42 66`，4种相机，各593帧，总计2372个样本。
  同状态恢复的最大数值误差约为 `1.49e-8`。
- 另对29种配置作全120条轨迹、9328帧的方块8顶点视锥检查。
  近距离45°视场造成430/529帧部分方块顶点越界，因而不推荐。
  推荐配置及较高备选在这些位置中没有方块顶点越界。
  此检查使用了全源数据中的物体位姿，仅用于离线视场覆盖预检；不是对遮挡的验证。
- 垂直俯视在5条筛选轨迹中大部分帧原始方块点为0，实际被机器人遮挡，故不推荐。
  这说明“顶点在视锥内”不等于“物体可见”。
- 推荐配置及较高备选分别执行episode `9 27 66` 的真实关节动作回放，
  各253帧、3条最终成功，推荐配置的方块点为FPS512最少4、中位数11。
  回放存在小的数值轨迹差异，并非逐位复现。统计的最大状态误差混合了
  位置/速度/关节等原单位，不应解读成米或毫米。
- `snapshot` 模式是保存状态的重渲染，不执行任务；其phase仅根据物体高度和
  末端距离标记 `approach / near_contact / lifted`。`action_replay`才真实执行动作，
  可读取当时的抓取标记。专家回放成功不代表新相机下已训练策略的成功率。
- 实体ID和物体位姿仅用于计数、上色、相机可见性检查。点选择依旧是有效点过滤、
  基座系crop、4096点随机预采样、普通FPS，没有语义保底、复制点或合成不可见表面。
- 以下结果仅适用于PickCube；另外四个任务已分别进行小批量比较和完整状态重渲染，
  见MULTI_TASK_REPORT.md，不能直接套用PickCube参数。

## 文件与复现

| 文件/目录 | 内容 |
| --- | --- |
| `camera_experiment.py` | 候选参数、同状态重渲染、完整轨迹验证和真实动作回放 |
| `check_frustum.py` | 全源轨迹的方块8顶点视锥预检，并核对实际相机内外参约定 |
| `analyse_cameras.py` | 排名、推荐参数导出、RGB/语义点云/方块局部对照图 |
| `verify_recordings.py` | 验证每个FPS点的源像素、实体ID、坐标还原和距离通道 |
| `multi_task_experiment.py` / `analyse_multi_task.py` | 另外四个任务的相机比较、实体审计与对照图 |
| `runs/screen01` / `screen02` | 两轮筛选录制、manifest、每帧CSV和summary |
| `runs/validation01` | 4配置×7条完整轨迹的记录 |
| `runs/replay01` / `replay02` | 较高备选和最终推荐配置的真实动作回放 |
| `runs/frustum01.json` | 29配置×9328帧的几何视场覆盖预检 |
| `runs/final-report/analysis.json` | 完整统计与推荐理由 |
| `runs/final-report/camera-preset.json` | 筛选阶段导出的sensor_configs和点云参数；正式接入见INTEGRATION.md |
| `runs/final-report/comparison-*.png` | 各阶段同场景RGB、FPS512分布和物块原始/采样点对照 |
| `runs/integrity01.json` / `integrity02.json` | 共4558帧、9116份FPS数组的完整性检查 |

HDF5按 `traj_<源ID>/frame_<帧号>` 保存原生RGB、segmentation、裁剪后基座系XYZ、
原像素索引、原始物块XYZ、TCP/相机矩阵、FPS512/1024特征和采样索引。
保留的是用于审计的实验记录，未封装成FlowDP3正式训练数据。
原始像素索引对应同组的segmentation/RGB图；通过索引能核对每一个采样点属于哪个实体。

从项目根目录重跑小批量对照，须使用新的输出目录；程序拒绝覆盖现有结果：

```bash
.venv-ppu/bin/python -B testpointcloud/camera_experiment.py \
  --cameras legacy128_90 low_left256_60 balanced_right256_50 \
  --episodes 9 27 66 --frames 0 \
  --output testpointcloud/runs/my-camera-validation

.venv-ppu/bin/python -B testpointcloud/camera_experiment.py \
  --mode action_replay --cameras low_left256_60 \
  --episodes 9 27 66 \
  --output testpointcloud/runs/my-camera-replay
```

筛选阶段没有改正式入口。后续用户授权的接入已将相机和crop写入新v2契约，并统一
采集、评估和可视化入口；真实回放转换的新训练数据及检查见INTEGRATION.md。

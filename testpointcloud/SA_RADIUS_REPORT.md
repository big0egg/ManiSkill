# PickCube：SA1 / SA2 半径对照实验

日期：2026-10-07。实验程序、输出与本文均位于 `testpointcloud`；实验阶段未修改正式模型、采样入口和配置。实验后的正式参数接入见文末。

## 结论

**半径会明显改变当前 512 点输入的邻域组成，值得调整；它不会增加 FPS 保留下来的方块点数或方块中心数。** SA1 从 0.10m 缩到 0.05m，方块中心邻域的方块点占比从 **35.7% 增至 59.1%**，桌面点占比从 **41.0% 降至 23.9%**。SA2 从 0.20m 缩到 0.12m，**98.3% 的 SA2 邻域发生改变**，平均有效邻居从 **29.7 降至 17.4**。

在这些专家状态中，`SA1=0.05m / SA2=0.12m` 保持了所有输入方块点到 SA2 的几何路径。继续缩到 `0.03m / 0.06m` 时，512 点配置的最差帧只剩 **18.2%** 的输入方块点能到达 SA2，不能一味追求更小的半径或更高的目标占比。

这些结果证明的是**邻域组成与信息传递路径的变化**。没有训练后的 checkpoint，也没有执行策略成功率评估，因此不能宣称新半径改善了抓取成功率或已经解释了当前失败原因。程序支持后续加载真实 EMA 编码器权重做特征敏感性检查；本次没有使用随机权重生成任何“模型效果”结论。

## 实验范围与控制变量

- 源记录：`runs/validation01/low_left256_60.h5`，7 条成功专家轨迹，源 ID 为 `1 / 3 / 9 / 19 / 27 / 42 / 66`，共 **593 帧**。
- 同一帧在所有半径组合中使用同一份已经保存的点云，不重新渲染或重新采样。相机固定为 eye=`(0.30,-0.30,0.35)`、target=`(0,0,0.12)`、256×256、FOV60°。
- crop 固定为基座系 min=`(0.44,-0.23,-0.03)`、max=`(0.79,0.25,0.52)`；点云为基座轴向下相对 TCP 的 `[dx,dy,dz,norm]`，`length_scale=1`，半径单位为米。
- 分别固定三种背景配置：**512 点 + 128/32 中心**、**1024 点 + 128/32 中心**、**1024 点 + 256/64 中心**。每个配置内部只改变半径，两层邻居上限一直为 32。
- SA1 半径：`0.03 / 0.04 / 0.05 / 0.07 / 0.10 / 0.15m`；SA2 半径：`0.06 / 0.08 / 0.10 / 0.12 / 0.16 / 0.20 / 0.30m`。共 **126 个配置、74,718 个帧/配置配对记录**。
- 调用正式编码器的 `farthest_point_indices` 和 `ball_query_indices`。Actor / Link ID 只用于标注计数，没有进入中心选择、邻域查询或模型输入。

阶段标签为 `approach: 145 帧 / near_contact: 315 帧 / lifted: 133 帧`。这些标签来自原相机实验中物体高度与 TCP 距离的启发式划分，`near_contact` 不等于真实抓取或闭爪事件；本次没有策略失败轨迹。

## 指标是什么意思

**方块中心邻域的方块点占比**：先找出 SA1 中心里实际落在方块上的点，再计算这些中心各自有效邻居中的方块比例，先对一帧的中心平均，再对帧平均。它衡量几何邻域的实体组成，不是 attention 权重、学习后的贡献比例，也不是最终 512 点里的方块占比。512 点配置有 4 帧没有方块中心，因此该指标按其余 **589 帧**统计；1024 点 + 128/32 中心按 **590 帧**统计；1024 点 + 256/64 中心按全部 **593 帧**统计。没有方块中心的帧仍参加路径覆盖与邻居数量统计。

**到达 SA2 的方块点覆盖率**：追踪每个输入方块点是否进入至少一个 SA1 有效邻域，以及该 SA1 特征是否进入至少一个 SA2 有效邻域。这是计算图中的潜在通路；MLP、最大池化或最终 readout 仍可能没有保留/利用对应特征。100% 路径覆盖不能当成“全部几何信息被完整编码”。

**邻域改变比例**：同一帧、相同中心下，与原半径 `0.10 / 0.20m` 比较有效邻居集合。半径改变不影响两层的 FPS 中心，因此这种逐中心比较成立。平均有效邻居数量包含全部中心，最大为 32，中心自身也算一个邻居。

## SA1 单独变化：当前 512 点、128/32 中心

此表保持 SA2=0.20m。各列为逐帧统计的平均值；覆盖率列给出最差帧。

| SA1 半径 | SA1 平均有效邻居 | 方块中心邻域中方块占比 | 最差帧的方块点到 SA2 覆盖率 |
| --- | ---: | ---: | ---: |
| 0.15m | 31.9 | 34.7% | 100% |
| **原配置 0.10m** | **31.1** | **35.7%** | **100%** |
| 0.07m | 27.2 | 38.8% | 100% |
| **0.05m** | **16.5** | **59.1%** | **100%** |
| 0.04m | 10.7 | 74.3% | 100% |
| 0.03m | 6.3 | 84.5% | 70.0% |

0.05m 改变了平均 **98.1% 的方块中心邻域**，因此是实质性的局部尺度调整。在 `near_contact` 阶段，方块中心邻域中方块占比从 **33.5% 增至 52.0%**。0.04m 进一步提高目标占比，但平均邻居数量较少；0.03m 已经出现输入方块点没有被 SA1 接收的情况。

## SA2 单独变化：当前 512 点、128/32 中心

此表保持 SA1=0.10m。SA2 邻居是 SA1 中心对应的特征，不是原始点。

| SA2 半径 | SA2 平均有效邻居 | 相比 0.20m 改变的 SA2 邻域比例 | 最差帧的方块点到 SA2 覆盖率 |
| --- | ---: | ---: | ---: |
| 0.30m | 31.8 | 28.4% | 100% |
| **原配置 0.20m** | **29.7** | **0%** | **100%** |
| 0.16m | 25.5 | 62.2% | 100% |
| **0.12m** | **17.4** | **98.3%** | **100%** |
| 0.10m | 12.6 | 99.98% | 100% |
| 0.08m | 8.2 | 100% | 100% |
| 0.06m | 5.0 | 100% | 100% |

这个表不能单独证明 0.06m 合适：此时 SA1 仍有 0.10m 的较大范围，方块点进入了较多第一层邻域。**两层同时缩小**会产生不同结果，见下表。

## 联合变化与 1024 点对照

| 输入点 / SA 中心 | 半径 SA1 / SA2 | 方块中心邻域中方块占比 | SA1 / SA2 平均有效邻居 | 最差帧到 SA2 的方块点覆盖率 |
| --- | --- | ---: | --- | ---: |
| 512 / 128,32 | 0.10 / 0.20m | 35.7% | 31.1 / 29.7 | 100% |
| 512 / 128,32 | **0.05 / 0.12m** | **59.1%** | **16.5 / 17.4** | **100%** |
| 512 / 128,32 | 0.04 / 0.10m | 74.3% | 10.7 / 12.6 | 100% |
| 512 / 128,32 | 0.03 / 0.06m | 84.5% | 6.3 / 5.0 | **18.2%** |
| 1024 / 128,32 | 0.10 / 0.20m | 60.2% | 31.8 / 29.7 | 100% |
| 1024 / 128,32 | 0.05 / 0.12m | 64.9% | 27.7 / 17.4 | 100% |
| 1024 / 128,32 | 0.03 / 0.06m | 84.8% | 12.5 / 5.0 | **14.3%** |
| 1024 / 256,64 | 0.10 / 0.20m | 58.5% | 31.9 / 31.8 | 100% |
| 1024 / 256,64 | **0.05 / 0.12m** | **62.5%** | **28.6 / 28.8** | **100%** |
| 1024 / 256,64 | 0.04 / 0.10m | 70.7% | 22.6 / 25.3 | 100% |
| 1024 / 256,64 | 0.03 / 0.06m | 79.5% | 13.2 / 10.6 | 100% |

最小半径 `0.03 / 0.06m` 下，512 点 + 128/32 中心有 **242/593 帧**发生部分方块点通路丢失；1024 点 + 128/32 中心有 **298/593 帧**；1024 点 + 256/64 中心没有这类丢失。这说明点数、中心密度与半径必须配合。全部 126 个配置都没有整帧方块通路完全消失，但部分点通路丢失仍可能影响局部精度。

一个最差实例：`traj_3 / frame_00038`，512 点中有 11 个方块点。`0.03 / 0.06m` 下只有 **2/11** 保持到 SA2 的路径；方块中心邻域的“纯度”此时是 100%。因此高纯度本身不是足够的选择标准。

## 为什么 1024 点下半径影响不同

当前查询取的是“半径内**最近的最多 32 个点**”，并不聚合球内全部点。输入更密后，这 32 个邻居通常已经较近，较大的半径更多只是上限。

在原半径下，有完整 32 个邻居的方块 SA1 中心，其第 32 个邻居距离中位数为：

| 输入 / 中心配置 | 距离中位数 |
| --- | ---: |
| 512 / 128,32 | 6.60cm |
| 1024 / 128,32 | 4.72cm |
| 1024 / 256,64 | 4.47cm |

所以 SA1 从 10cm 缩到 5cm，对 512 点的改变较大；对 1024 点 + 256/64 中心，方块中心邻域改变比例为 **32.0%**，目标占比只从 58.5% 增至 62.5%。缩到 4cm 后，该改变比例为 **78.4%**，目标占比为 70.7%。

放大半径对照也支持上限效应：1024 点 + 256/64 中心的 SA1 从 10cm 放到 15cm，仅改变 **1.25% 的全部 SA1 邻域**；SA2 从 20cm 放到 30cm，仅改变 **1.90% 的全部 SA2 邻域**。当前 512 点下，放大 SA2 仍会改变 28.4% 的邻域，因此不能把“几乎不变”的结论套到所有点密度。

## 下一轮参数建议

如果优先验证半径的作用、尽量降低数据与算力成本，使用现有 **512 点、128/32 中心**，先尝试 **0.05 / 0.12m**。点云数据可以复用，半径属于编码器设置；应在新训练/微调中采用新半径并在评估时保持一致，不能直接把旧模型换半径后的效果当成公平训练对照。

如果同时推进 1024 点方案，**1024 点、256/64 中心、0.05 / 0.12m** 是较保守候选；**0.04 / 0.10m** 在当前数据中更集中于目标、邻居数量仍较充足，可作为更细尺度候选。仅凭几何统计不能在两者间选出成功率最佳值。没有理由直接采用 0.03 / 0.06m 作为默认配置。

半径调整改变局部混合范围，FPS 点数改变可用几何密度，中心数改变表示的空间分布，三者不是同一个作用。实验阶段正式程序未改动上述参数。
